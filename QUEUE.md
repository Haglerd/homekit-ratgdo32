### [P2] log-audit-20260517-002 — tickDrift telemetry shows -150000ms repeatedly after cadence-transition / fast-arm events (.84 regression)
**Status:** queued
**Source:** log-audit 2026-05-17 05:00 (Pi syslog + device endpoints, 5h post-.84 boot, 180 lines)
**Issue:** (not filed)
**Acceptance:** `tickDrift` reflects actual loopTask-vs-expected-wall-clock skew; transitions between fast (30s) and slow (180s) sampler cadence MUST update the `lastSampleMs` reference so the next sample reports the true single-interval drift, not the abandoned-interval delta. Post-fix: tickDrift values stay in single-digit to ~100ms range during steady state (matching pre-.84 baseline of `68ms`), -150000ms artifacts disappear, no false-positive watchdog signals downstream.
**Notes:** P2 observability — NEW pattern not seen in any prior audit. In a 5h window with 4 heap-watermark-trigger fast-arm events and ~10 cadence transitions, tickDrift readings: 40 samples at exactly -150000ms (±1, =180s-30s sampler delta), 8 at 0ms, plus outlier transition-edges -131061ms, -82999ms, -14013ms, 3950ms. Pre-.84 baseline (last audit 2026-05-16) was `tickDrift=68ms` steady-state. The new helper `homekit_health_arm_fast_mode_if_low()` (PR #132 .84 fix) likely re-arms the sampler timer without writing the `lastSampleMs` reference used by the tickDrift calculation, so the next sample computes `(now - lastSampleMs)` against a stale reference set 180s ago even though the new cadence is 30s — diff = 30000 - 180000 = -150000. Same effect on the reverse 30→180 transition explains the -82999 / -131061 mid-transition outliers. NO functional impact observed (no false watchdog level transitions, no panic, hkHealthyTicks counter unaffected). But pollutes diag-hk telemetry: future log-audits using tickDrift to spot real wall-clock skew (25-day uptime cast bug class) will be flooded with these artifacts. Code site to inspect: the helper added in .84 + the diag-hk `lastSampleMs` math in `homekit.cpp` (relate to `tickDriftMs` fix from PR #130 review which was a separate issue). Auto-fix-eligibility: **auto-fixable** — single-file diff likely sufficient: have `homekit_health_arm_fast_mode_if_low()` update `lastSampleMs = now` when it re-arms, OR add an `armed_via_fast_mode` flag to skip the next tickDrift comparison.
